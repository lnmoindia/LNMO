# LNMO — Multi-tenant School ERP SaaS — PRD

## Original problem statement
Build LNMO: a multi-tenant School ERP (React + FastAPI + MongoDB) with Platform Console, Institution Console, Teacher Workspace, Student Portal, Parent Portal (later). Premium modern SaaS shell, left sidebar + topbar, light/dark, multilingual-ready. Full route map, layout inventory, module inventory, and sprint build order provided by user (see conversation).

## User choices
- Auth: JWT custom email/password
- MVP priority: Platform Console + Institution Admin core
- i18n: English only for now (structure ready for more)
- Seed: NO demo data (empty start); platform admin seeded from env
- Branding: "LNMO", design decided by design agent (Swiss Technical Utility, indigo/slate/amber, Outfit + Inter)

## User personas
- Platform Admin (LNMO operator): manages tenants, institutions, plans, audit
- Institution Admin: manages students, teachers, users, classes, sections, subjects, settings
- Teacher / Student / Staff: portals pending (coming-soon page)
- Parent: later

## Architecture
- Backend: FastAPI single server.py — JWT auth (httpOnly cookies + bearer fallback, bcrypt, brute-force lockout 5/15min, refresh tokens), generic `/api/res/{resource}` CRUD (platform-scoped: tenants, institutions, plans; institution-scoped: students, teachers, classes, sections, subjects), `/api/users` management, `/api/institution/profile`, `/api/platform/stats`, `/api/institution/stats`, `/api/audit`. Audit logging on all mutations. Cascade delete on institution removal. UUID string ids.
- Frontend: React — AuthContext, ThemeContext (light/dark, localStorage lnmo-theme), AppShell (dark sidebar + topbar), generic ResourcePage (search/pagination/CRUD dialogs) driven by configs, dashboards with stat cards + quick actions + activity feed, role-guarded routes.

## Phase 1 — Principal role (elevated teacher), backend only (Sept 2026)
- NEW collection `principal_assignments`: {id, user_id, institution_id, scope_type ("whole_school"|"units"), unit_ids[], designation ("principal"|"assistant_principal"), assigned_by, created_at}.
- DESIGN: a principal is NOT a new account type — the user keeps role=="teacher" and gains a principal_assignment row. This keeps all teacher endpoints working for free (combined portal) and makes revoke = delete the row (re-checked every request). `/auth/me` now returns is_principal + principal {scope_type, unit_ids, designation}.
- NEW endpoints (Pydantic request models, institution_admin only): GET/POST/PUT/DELETE /api/principals. Designation auto-defaults (first in scope = principal, next = assistant_principal); explicit principal on an occupied scope → 400; one principal title per unit and one per whole-school bucket; identical permissions (title is display-only). Validates teacher belongs to institution (cross-institution/non-teacher → 400); units must exist.
- PERMISSIONS: principals get institution-admin management powers but scoped. Enforcement is server-side and centralized: check_scope() admits principals to institution resources except excluded; apply_principal_scope_query()/_doc_in_principal_scope() narrow generic /api/res/{resource} list/create/update/get/delete by academic_unit_id (classes) or class_name (students, sections, enrollments, teacher_assignments, subject_offerings, assessments, achievements). guard_principal_class() gates custom endpoints (attendance, marks/publish, timetable entries, students/enroll+bulk, portal/parent user, class detail, subject-offerings bulk, students/filter, teachers list, institution/stats, lookups).
- EXCLUSIONS (principals get 403 even via direct API): institution/profile (settings), academic-config, setup-status, /res/academic_units, /res/academic_years, /api/users CRUD, and /api/principals (assign/revoke). Teacher ACCOUNT create/update/delete limited to institution_admin + WHOLE-SCHOOL principals (teacher accounts have no unit affinity); unit principals can LIST teachers filtered to their units.
- CASCADES: deleting an academic unit prunes it from assignments (empties → removed); deleting/deactivating a teacher removes principal access (active_principal returns None for inactive); institution delete cascades principal_assignments.
- OPENAPI moved to /api/openapi.json (docs /api/docs) so it's reachable through the /api ingress.
- TESTS: backend/tests/test_principal_phase1.py — 18/18 pass. Runs the app in-process via TestClient against a SEPARATE throwaway DB (lnmo_principal_phase1_test, dropped after); real DB never touched. Covers assign/revoke, designation rules, one-principal-per-scope, all exclusion 403s, scope-leak attempts (unit-A principal can't see unit-B students/classes/attendance), assistant==principal perms, whole-school reach, principals retaining teacher endpoints, unit-delete cleanup, revocation revert.
- DEVIATION (documented): kept users.role=="teacher" instead of setting role=="principal" (brief allowed "your call"); this guarantees teacher-guard compatibility and clean revoke.
